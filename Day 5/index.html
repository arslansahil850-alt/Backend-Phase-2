Introduction & Prerequisites

What & Why HTTP?

Every time you browse a website, click a button, or fetch data in an application, your browser communicates with a remote server using HTTP (Hypertext Transfer Protocol).

As a backend developer, understanding HTTP is non-negotiable. You are building systems that receive HTTP requests, parse headers, evaluate methods, and return precise HTTP responses with correct status codes.

Prerequisites

  • Day 04 Knowledge: Familiarity with Node runtime and asynchronous scripts.
  • Client-Server Awareness: Knowing that browsers request data and servers fulfill it.
  • Basic URL Structure: Understanding domains, paths, and query parameters.

Detailed Lessons & Code Demonstrations

Lesson 5.1

The HTTP Request-Response Cycle

HTTP is a stateless, client-server protocol. The client initiates a TCP connection, sends an HTTP request message, and the server processes it and returns an HTTP response message before closing or keeping the connection alive.

Client (Browser / Postman)
→ Request (Method + URL + Headers) →
← Response (Status + Headers + Body) ←
Node.js Server
Lesson 5.2

HTTP Status Codes Breakdown

Status codes inform the client about the outcome of their request. They are grouped into 5 distinct classes:

  • 2xx (Success): Request was received and processed successfully (e.g., `200 OK`, `201 Created`).
  • 3xx (Redirection): Further action is needed to complete the request (e.g., `301 Moved Permanently`).
  • 4xx (Client Error): The request contains bad syntax or unauthorized data (e.g., `400 Bad Request`, `401 Unauthorized`, `404 Not Found`).
  • 5xx (Server Error): The server failed to fulfill a valid request due to an internal bug (e.g., `500 Internal Server Error`).
Lesson 5.3

Anatomy of HTTP Messages

An HTTP message consists of a start line, optional headers, an empty line separator, and an optional message body.

Raw HTTP Request Example 
GET /api/users HTTP/1.1
Host: localhost:3000
User-Agent: Mozilla/5.0
Accept: application/json
Raw HTTP Response Example 
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Content-Length: 45

{ "success": true, "data": ["Arslan", "Ali"] }

Practical Exercises

Easy

Exercise 1: Status Code Matcher

Identify which status code (200, 201, 400, 404, or 500) corresponds to: "A new user resource was successfully created."

201 Created — The standard HTTP status code for successful resource creation.

Medium

Exercise 2: Identifying Client vs Server Errors

Explain the difference between a 4xx status code and a 5xx status code.

4xx represents a client-side error (bad request, missing auth, invalid URL). 5xx represents a server-side error (database crash, internal unhandled exception).

Medium

Exercise 3: Semantic HTTP Methods

Which HTTP method should be used to completely replace or update an existing user record?

PUT (or PATCH for partial updates).

Hard

Exercise 4: Content-Type Header Purpose

What is the purpose of the `Content-Type: application/json` header in an HTTP response?

It informs the client browser or consumer that the transmitted response body is formatted as structured JSON data so it can parse it correctly.

Hard

Exercise 5: Idempotency in HTTP Methods

Which common HTTP methods are considered idempotent (making multiple identical requests produces the exact same server state as making a single request)?

GET, PUT, DELETE are idempotent. POST is not idempotent (making two POST requests creates two duplicate resources).

Daily Project: HTTP Protocol Inspector CLI

Build an HTTP Request Simulator & Status Analyzer

Project Phase 2 - Day 05

Description: Build a Node.js CLI tool that simulates incoming HTTP requests with different methods and paths, evaluates status codes, and outputs structured response summaries.

Key Requirements:

  • Define mock request objects containing method, path, and headers.
  • Write a response analyzer function that returns semantic status messages.
  • Format terminal output cleanly.
http-inspector.js 
// HTTP Protocol Simulator & Inspector
const requests = [
    { method: 'GET', path: '/api/users', statusCode: 200 },
    { method: 'POST', path: '/api/users', statusCode: 201 },
    { method: 'GET', path: '/api/admin', statusCode: 401 },
    { method: 'GET', path: '/missing-page', statusCode: 404 },
    { method: 'PUT', path: '/api/crash', statusCode: 500 }
];

function analyzeResponse(req) {
    let category = "Unknown";
    if (req.statusCode >= 200 && req.statusCode < 300) category = "SUCCESS (2xx)";
    else if (req.statusCode >= 300 && req.statusCode < 400) category = "REDIRECTION (3xx)";
    else if (req.statusCode >= 400 && req.statusCode < 500) category = "CLIENT ERROR (4xx)";
    else if (req.statusCode >= 500) category = "SERVER ERROR (5xx)";

    return {
        ...req,
        category
    };
}

console.log("==================================================");
console.log("       ARSLAN HTTP PROTOCOL INSPECTOR CLI         ");
console.log("==================================================");

requests.forEach(req => {
    const res = analyzeResponse(req);
    console.log(`[${res.method}] ${res.path} → Status: ${res.statusCode} (${res.category})`);
});
console.log("==================================================");

Conceptual Knowledge Checks

True or False

1. HTTP is a stateful protocol that remembers every user connection permanently.

FALSE: HTTP is stateless by design. Each request is independent.

2. Status code 404 means the requested resource was not found on the server.

TRUE: 404 is the standard client error for missing resources.

3. A POST request is idempotent.

FALSE: Multiple identical POST requests create multiple duplicate resources.
