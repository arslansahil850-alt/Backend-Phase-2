Introduction & Prerequisites

What & Why Backend Development?

In web development, the Frontend is everything users see and touch (UI, CSS animations, HTML structure). However, the Backend is the digital engine room operating behind the scenes.

Backend engineering deals with data persistence (databases), security, user authentication, file storage, payment gateways, and business logic processing. Without a backend, web applications are static displays unable to store user states or perform computations securely.

Prerequisites

  • JavaScript ES6+ Knowledge: Arrow functions, Promises, Destructuring, Async/Await (Completed in Phase 1).
  • Terminal/CLI Basics: Navigating directories (`cd`, `ls`/`dir`), running terminal scripts.
  • Basic HTTP Understanding: What happens when you type a URL into a browser address bar.

Lesson 1.1

The Client-Server Architecture

Every web transaction operates on a client-server architecture model. The client (web browser, mobile app, CLI tool) sends an HTTP Request over the internet, and the backend server receives, processes, queries the database if needed, and returns an HTTP Response.

Browser (Client)
→ HTTP Request (GET/POST) →
← HTTP Response (JSON/HTML) ←

Lesson 1.2

What is Node.js? (V8 + C++ Bindings + libuv)

Node.js is not a programming language, nor is it a framework. Node.js is an open-source, cross-platform JavaScript Runtime Environment built on top of Google Chrome’s V8 JavaScript Engine.

Before Ryan Dahl created Node.js in 2009, JavaScript could only execute inside browsers. Node.js extracted Google's high-performance C++ V8 Engine and paired it with libuv (a multi-platform C library for asynchronous I/O) to allow JS code to access the local file system, network interfaces, operating system processes, and hardware directly.

Lesson 1.3

Node.js Global Objects & CLI Tooling

In browser JavaScript, the top-level global object is `window`. In Node.js, there is no `window` or `document` object because there is no DOM. Instead, Node provides the `global` object along with specialized system globals.

index.js 
// Node Globals Demo
console.log("Global object check:", global === globalThis); // true

// Directory & File Paths
console.log("Current Directory (__dirname):", __dirname);
console.log("Current File (__filename):", __filename);

// Process Object (System info & Environment)
console.log("Node Version:", process.version);
console.log("Platform ID:", process.platform);
console.log("Process ID (PID):", process.pid);
Line-by-Line Breakdown:
  • __dirname: Provides the absolute path to the directory where the executing script resides.
  • __filename: Returns the absolute file path including the filename itself.
  • process: A global object that exposes details about the current Node.js execution environment and operating system.
Lesson 1.4

Non-Blocking Asynchronous Event Loop

Node.js operates on a single thread using an Event-Driven, Non-Blocking I/O Architecture. Traditional servers (like traditional Apache PHP) create a new system thread for every incoming connection. When thousands of connections hit simultaneously, RAM and memory overhead explode.

Node handles requests concurrently by delegating time-heavy I/O operations (file reading, network queries) to C++ system threads via libuv, continuing to run JS code, and handling callbacks when the disk or network responds.

async-demo.js 
console.log("1. Starting main server process execution...");

// Simulating a non-blocking background I/O operation (e.g. database query)
setTimeout(() => {
    console.log("2. Async Operation Completed (Database result fetched)");
}, 2000);

console.log("3. Server ready to handle next incoming client request!");
Expected Terminal Output: 
1. Starting main server process execution...
3. Server ready to handle next incoming client request!
2. Async Operation Completed (Database result fetched)

Daily Project: Server Health Monitor CLI

Build a Terminal System & Process Inspector

Project Phase 2 - Day 01

Description: Build an interactive CLI backend script that displays real-time server operating metrics, CPU architecture, memory allocations, uptime, and system execution parameters in a beautifully formatted log output.

Key Requirements:

  • Capture CLI flags passed during launch (e.g. `--verbose` or `--json`).
  • Format process execution uptime using `process.uptime()`.
  • Print system memory status with formatted MB metrics.
  • Display Node runtime version and operating system platform.
system-monitor.js 
// System & Server Process Monitor CLI Tool
const args = process.argv.slice(2);
const isJsonMode = args.includes('--json');

function getSystemMetrics() {
    const memory = process.memoryUsage();
    return {
        timestamp: new Date().toISOString(),
        nodeVersion: process.version,
        platform: process.platform,
        architecture: process.arch,
        processId: process.pid,
        uptimeSeconds: Math.floor(process.uptime()),
        memory: {
            rssMB: (memory.rss / 1024 / 1024).toFixed(2),
            heapTotalMB: (memory.heapTotal / 1024 / 1024).toFixed(2),
            heapUsedMB: (memory.heapUsed / 1024 / 1024).toFixed(2)
        }
    };
}

if (isJsonMode) {
    console.log(JSON.stringify(getSystemMetrics(), null, 2));
} else {
    const metrics = getSystemMetrics();
    console.log("==========================================");
    console.log("       ARSLAN BACKEND SERVER MONITOR      ");
    console.log("==========================================");
    console.log(`Timestamp     : ${metrics.timestamp}`);
    console.log(`Node Version  : ${metrics.nodeVersion}`);
    console.log(`Platform      : ${metrics.platform} (${metrics.architecture})`);
    console.log(`PID           : ${metrics.processId}`);
    console.log(`Server Uptime : ${metrics.uptimeSeconds} seconds`);
    console.log("------------------------------------------");
    console.log(`Memory Usage  : ${metrics.memory.heapUsedMB} MB / ${metrics.memory.heapTotalMB} MB`);
    console.log("==========================================");
}

Conceptual Knowledge Checks

True or False

1. Node.js is a multi-threaded web application framework.

FALSE: Node.js is a single-threaded runtime environment using non-blocking I/O.

2. The `window` object is available inside Node.js scripts.

FALSE: `window` is browser-only. Node uses `global` or `globalThis`.

3. Node.js leverages Chrome's V8 C++ Engine to execute JavaScript.

TRUE: V8 compiles JS directly into machine code.

Quick Concepts

1. What library provides Node.js with its non-blocking event loop?

Answer: libuv, an asynchronous multi-platform C library.

2. How do you pass execution arguments to a Node script?

Answer: Via terminal CLI inputs accessed in code through `process.argv`.

3. What is the main benefit of non-blocking I/O?

Answer: It allows the server to handle concurrent connections without blocking execution while waiting for disk/network I/O.

Day 01 Quick Revision Cheat-Sheet

V8 Engine

Google's high-performance engine that compiles JavaScript straight to native machine instructions.

Path Globals

__dirname gives current folder path. __filename gives full script file path.

Process Object

Exposes hardware info, environment variables, system arguments, and process termination functions.

Non-Blocking I/O

Asynchronous operations are offloaded, freeing the single thread to execute further code concurrently.
