Introduction & Prerequisites

What & Why npm?

No backend developer builds everything from absolute scratch. npm (Node Package Manager) is the world's largest software registry where developers share open-source packages, libraries, and tools.

With npm, you can instantly install robust tools like Express.js, Lodash, or Dotenv with a single terminal command. Understanding `package.json` and clean project structure is paramount for building production-grade applications.

Prerequisites

  • Day 02 Knowledge: Understanding CommonJS modules (`require()` and `module.exports`).
  • Terminal CLI Experience: Running commands in your terminal or command prompt.
  • Node.js Installed: Ensuring Node and npm are correctly configured on your machine.

Detailed Lessons & Code Demonstrations

Lesson 3.1

Initializing Projects & Understanding `package.json`

Every Node project requires a manifest file named package.json located in the root directory. This file tracks installed packages, project scripts, version numbers, and metadata.

package.json Example 
{
  "name": "arslan-backend-api",
  "version": "1.0.0",
  "description": "Professional backend learning platform project",
  "main": "src/index.js",
  "scripts": {
    "start": "node src/index.js",
    "dev": "node --watch src/index.js"
  },
  "keywords": ["node", "express", "backend"],
  "author": "Arslan Sahil",
  "license": "MIT",
  "dependencies": {
    "dotenv": "^16.4.5"
  },
  "devDependencies": {
    "nodemon": "^3.1.0"
  }
}
Key Properties Breakdown:
  • scripts: Custom shortcuts for running terminal commands (e.g., `npm run start`).
  • dependencies: Packages required for the application to run in production.
  • devDependencies: Packages needed only during local development (like live-reload tools).
Lesson 3.2

Semantic Versioning (SemVer) Explained

npm packages follow Semantic Versioning formatted as MAJOR.MINOR.PATCH (e.g., `16.4.5`).

  • MAJOR (16): Incremented for breaking changes that break backward compatibility.
  • MINOR (4): Incremented when new features are added in a backward-compatible manner.
  • PATCH (5): Incremented for backward-compatible bug fixes.

The caret symbol (^) in front of version numbers (e.g., ^16.4.5) tells npm it is safe to automatically update minor and patch versions during `npm install`.

Lesson 3.3

Professional Backend Project Structure

Never dump all your code into a single file. Professional backend architecture separates concerns into dedicated directories.

Recommended Project Layout 
arslan-backend/
├── node_modules/
├── src/
│   ├── config/       # Database & environment configurations
│   ├── controllers/  # Request handler logic
│   ├── models/       # Database schemas and data models
│   ├── routes/       # API endpoints routing
│   ├── middleware/   # Custom middleware functions
│   └── index.js      # Main application entry point
├── .env              # Environment variables
├── package.json      # Dependencies manifest
└── package-lock.json # Exact dependency tree lockfile

Practical Exercises

Easy

Exercise 1: Interactive npm Initialization

Run `npm init` in your terminal to interactively generate a `package.json` file for your project. 

# Run in your project folder:
npm init
# Or bypass questions with default settings:
npm init -y
Medium

Exercise 2: Installing Dependencies & DevDependencies

Install `dotenv` as a standard dependency and `nodemon` as a development-only dependency via npm. 

npm install dotenv
npm install nodemon --save-dev
Medium

Exercise 3: Configuring Custom npm Scripts

Add a custom `"dev"` script inside your `package.json` that launches `nodemon src/index.js` automatically.

"scripts": {
  "start": "node src/index.js",
  "dev": "nodemon src/index.js"
}
# Execute in terminal using:
npm run dev
Hard

Exercise 4: Understanding `package-lock.json`

Explain why `package-lock.json` is crucial for team collaboration and reproducible builds across different machines.

package-lock.json locks down the exact dependency tree version numbers and cryptographic hashes downloaded, ensuring every developer on a team installs the exact same package versions without breaking changes.

Hard

Exercise 5: Safely Restoring `node_modules`

If your `node_modules/` folder is deleted or excluded from Git, how do you restore all project dependencies instantly?

# Simply run:
npm install
# npm will read package.json / package-lock.json and recreate node_modules automatically.

Daily Project: Professional CLI Dependency & Structure Generator

Build an Automated Project Scaffolding CLI Tool

Project Phase 2 - Day 03

Description: Build a Node.js utility script using built-in modules that automatically generates a professional backend folder structure (`src/config`, `src/controllers`, `src/routes`, `src/models`) and an initial `package.json` template.

Key Requirements:

  • Use Node's `fs` and `path` modules to create directories programmatically.
  • Generate a template `package.json` string automatically.
  • Output success confirmation logs to the terminal.
scaffold.js 
// Automated Backend Folder Structure Scaffolder
const fs = require('fs');
const path = require('path');

const folders = [
    'src/config',
    'src/controllers',
    'src/models',
    'src/routes',
    'src/middleware'
];

console.log("🚀 Initializing Arslan Backend Project Scaffolding...");

folders.forEach(folder => {
    const dirPath = path.join(process.cwd(), folder);
    if (!fs.existsSync(dirPath)) {
        fs.mkdirSync(dirPath, { recursive: true });
        console.log(`[Created Directory]: ${folder}`);
    } else {
        console.log(`[Already Exists]: ${folder}`);
    }
});

console.log("✅ Project structure successfully generated!");

Conceptual Knowledge Checks

True or False

1. The `node_modules/` folder should always be committed to Git version control.

FALSE: `node_modules` is massive and generated locally using `npm install`. It belongs in `.gitignore`.

2. `package.json` tracks project dependencies, scripts, and metadata.

TRUE: It serves as the central manifest for any Node project.

3. `devDependencies` are required for production server execution.

FALSE: DevDependencies are tools used during local development (like nodemon).

Quick Concepts

1. What command instantly initializes a `package.json` with default settings?

Answer: npm init -y

2. What do the three numbers in Semantic Versioning (`16.4.5`) represent?

Answer: MAJOR . MINOR . PATCH

3. What file locks down exact dependency versions and cryptographic hashes?

Answer: package-lock.json
