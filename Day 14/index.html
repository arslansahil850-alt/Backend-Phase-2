Introduction & Prerequisites

What & Why Environment Variables?

Hardcoding sensitive information like database passwords, API secret keys, and port numbers directly into your source code is a major security risk. If pushed to GitHub, your credentials are exposed instantly.

Environment variables allow you to inject configuration values dynamically into Node.js via process.env using the popular dotenv package.

Detailed Lessons & Code Demonstrations

Lesson 14.1

Configuring `dotenv` in Express

First install dotenv via npm install dotenv. Then require and configure it at the absolute top of your entry file before accessing any variables.

server.js 
// Load environment variables from .env file at top of file
require('dotenv').config();

const express = require('express');
const app = express();

const PORT = process.env.PORT || 3000;
const DB_URI = process.env.DATABASE_URI;

app.get('/', (req, res) => {
    res.json({
        success: true,
        environment: process.env.NODE_ENV || 'development',
        message: 'Environment variables loaded successfully!'
    });
});

app.listen(PORT, () => {
    console.log(`🚀 Server running on port ${PORT}`);
});
Key Takeaway:

Always place `require('dotenv').config()` at the very top of your main application file so variables are available everywhere.

Lesson 14.2

Creating `.env` and `.env.example` Files

Store your actual secrets in `.env`, and commit a template `.env.example` file to GitHub so other developers know what variables are required.

.env & .env.example 
# .env (KEEP SECRET - DO NOT COMMIT TO GITHUB)
PORT=5000
NODE_ENV=development
DATABASE_URI=mongodb://localhost:27017/my_database
JWT_SECRET=super_secret_jwt_key_98765

# .env.example (COMMIT TO GITHUB AS TEMPLATE)
PORT=3000
NODE_ENV=development
DATABASE_URI=your_connection_string_here
JWT_SECRET=your_jwt_secret_here

Daily Project: Secure Configured Express Backend

Build an Environment-Secured Express API

Project Phase 2 - Day 14

Description: Build an Express server that loads configuration from a `.env` file, validates required secrets on startup, and exposes a secure status endpoint.

Key Requirements:

  • Install and configure `dotenv`.
  • Validate that `PORT` and `API_KEY` exist in `process.env` on startup.
  • Create a secure `/api/v1/config-status` endpoint returning environment info.
server.js 
// Secure Configured Express Backend (Day 14 Project)
require('dotenv').config();

const express = require('express');
const app = express();

// 1. Startup Environment Validation Check
const requiredEnvVars = ['PORT', 'API_KEY'];
requiredEnvVars.forEach((key) => {
    if (!process.env[key]) {
        console.error(`❌ FATAL ERROR: Environment variable ${key} is missing.`);
        process.exit(1);
    }
});

const PORT = process.env.PORT || 3000;
const API_KEY = process.env.API_KEY;

app.use(express.json());

// 2. Public Route
app.get('/', (req, res) => {
    res.json({
        success: true,
        message: 'Welcome to Arslan Secure Backend API',
        environment: process.env.NODE_ENV || 'development'
    });
});

// 3. Protected Config Status Route
app.get('/api/v1/config-status', (req, res) => {
    const clientKey = req.headers['x-api-key'];

    if (!clientKey || clientKey !== API_KEY) {
        return res.status(401).json({ success: false, error: 'Unauthorized: Invalid API Key' });
    }

    res.json({
        success: true,
        status: 'SECURE',
        uptime: process.uptime(),
        nodeVersion: process.version
    });
});

app.listen(PORT, () => {
    console.log(`🚀 Secure server running on port ${PORT} in [${process.env.NODE_ENV || 'development'}] mode`);
});

Conceptual Knowledge Checks

True or False

1. You should commit your `.env` file containing secrets to public GitHub repositories.

FALSE: Never commit `.env` files; always add them to `.gitignore`.

2. `process.env` is a built-in global object in Node.js that holds environment variables.

TRUE: `process.env` is built directly into Node.js core.

3. `dotenv` automatically parses variables from a `.env` file into `process.env`.

TRUE: `require('dotenv').config()` populates `process.env`.

Quick Concepts

1. What npm package is used to load environment variables from a `.env` file?

Answer: dotenv

2. What built-in Node.js object stores runtime environment variables?

Answer: process.env

3. What file should you commit as a public template showing required environment variables?

Answer: .env.example
