Introduction & Prerequisites

What & Why Error Handling?

In production backends, things fail: databases go offline, users send invalid JSON, or requested records are missing. Uncaught exceptions will crash your Node.js process.

Express provides a specialized Error-Handling Middleware signature consisting of four parameters: (err, req, res, next). Placing this at the bottom of your middleware stack intercepts all runtime errors gracefully.

Prerequisites

  • Day 11 Knowledge: Deep understanding of middleware execution order and `next()`.
  • Async/Await: Familiarity with asynchronous JavaScript execution in Node.js.

Detailed Lessons & Code Demonstrations

Lesson 12.1

The 4-Parameter Error Middleware Signature

When Express detects an error passed via next(err) or thrown inside a synchronous handler, it skips all regular middleware and jumps straight to the nearest error-handling middleware (which must have 4 parameters).

error-demo.js 
const express = require('express');
const app = express();

app.use(express.json());

// Trigger an error route
app.get('/api/fail', (req, res, next) => {
    const err = new Error('Something went catastrophically wrong!');
    err.statusCode = 500;
    next(err); // Forwards error to error-handling middleware
});

// CENTRALIZED ERROR-HANDLING MIDDLEWARE (Must have exactly 4 parameters)
app.use((err, req, res, next) => {
    const statusCode = err.statusCode || 500;
    
    res.status(statusCode).json({
        success: false,
        error: {
            message: err.message || 'Internal Server Error',
            status: statusCode,
            stack: process.env.NODE_ENV === 'development' ? err.stack : undefined
        }
    });
});

app.listen(3000);
Key Takeaway:

Always define your error-handling middleware at the very bottom of your application after all routes and regular middleware.

Lesson 12.2

Handling Async Errors in Express

In Express 4 and earlier, errors thrown inside asynchronous functions (like database queries) are not automatically caught unless passed to `next(err)` or wrapped in try/catch blocks.

async-error.js 
// Async Route with Try/Catch Error Forwarding
app.get('/api/users/:id', async (req, res, next) => {
    try {
        const user = await fakeDatabaseFind(req.params.id);
        if (!user) {
            const error = new Error('User not found');
            error.statusCode = 404;
            throw error;
        }
        res.json({ success: true, data: user });
    } catch (err) {
        next(err); // Safely forwards error to error middleware
    }
});

        super(message);
        this.statusCode = statusCode;
        this.status = `${statusCode}`.startsWith('4') ? 'fail' : 'error';
        this.isOperational = true;
        Error.captureStackTrace(this, this.constructor);
    }
}

Daily Project: Production-Ready Error-Handled Express API

Build a Robust Backend with Centralized Error Handling

Project Phase 2 - Day 12

Description: Build an Express server featuring custom AppError classes, async try/catch handlers, 404 route interception, and a centralized 4-parameter error-handling middleware.

Key Requirements:

  • Implement a custom `AppError` class for operational errors.
  • Create robust GET and POST routes with validation and error forwarding.
  • Implement 404 catch-all middleware and centralized error middleware.
server.js 
// Production-Ready Error-Handled Express API
const express = require('express');
const app = express();
const PORT = 3000;

app.use(express.json());

// 1. Custom AppError Class
class AppError extends Error {
    constructor(message, statusCode) {
        super(message);
        this.statusCode = statusCode;
        this.status = `${statusCode}`.startsWith('4') ? 'fail' : 'error';
        this.isOperational = true;
    }
}

// In-Memory Database Simulation
let products = [
    { id: 1, name: 'Mechanical Keyboard', price: 89.99 },
    { id: 2, name: 'Gaming Mouse', price: 49.99 }
];

// 2. Routes
app.get('/api/products', (req, res) => {
    res.json({ success: true, count: products.length, data: products });
});

app.get('/api/products/:id', (req, res, next) => {
    const product = products.find(p => p.id === parseInt(req.params.id));
    
    if (!product) {
        return next(new AppError('Product not found with that ID', 404));
    }
    
    res.json({ success: true, data: product });
});

app.post('/api/products', (req, res, next) => {
    const { name, price } = req.body;
    
    if (!name || !price) {
        return next(new AppError('Please provide both product name and price', 400));
    }

    const newProduct = { id: products.length + 1, name, price };
    products.push(newProduct);

    res.status(201).json({ success: true, message: 'Product created', data: newProduct });
});

// 3. 404 Route Not Found Interceptor
app.all('*', (req, res, next) => {
    next(new AppError(`Can't find ${req.originalUrl} on this server!`, 404));
});

// 4. Centralized Error-Handling Middleware (4 Parameters)
app.use((err, req, res, next) => {
    err.statusCode = err.statusCode || 500;
    err.status = err.status || 'error';

    console.error(`❌ [ERROR]: ${err.message}`);

    res.status(err.statusCode).json({
        success: false,
        status: err.status,
        error: err.message,
        stack: process.env.NODE_ENV === 'development' ? err.stack : undefined
    });
});

app.listen(PORT, () => {
    console.log(`🚀 Error-handled API server active at http://localhost:${PORT}`);
});

Conceptual Knowledge Checks

True or False

1. Express error-handling middleware must take exactly four parameters: `(err, req, res, next)`.

TRUE: Express identifies error middleware by its 4-parameter signature.

2. Uncaught exceptions in Node.js will automatically crash the server process if left unhandled.

TRUE: Uncaught errors terminate the Node process to prevent unpredictable state.

3. Calling `next()` with an argument skips all subsequent normal middleware and jumps straight to error handlers.

TRUE: Passing any argument to `next()` tells Express an error occurred.

Quick Concepts

1. What function is called to forward an error downstream in Express?

Answer: next(err)

2. Where should error-handling middleware be positioned in your middleware stack?

Answer: At the very bottom after all routes and regular middleware.

3. What status code is standard for a resource that cannot be found?

Answer: 404 Not Found
