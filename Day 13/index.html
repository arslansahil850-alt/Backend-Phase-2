Introduction & Prerequisites

What & Why REST API Design?

REST (Representational State Transfer) is an architectural style for designing networked applications. A well-designed REST API is predictable, scalable, secure, and easy for frontend developers and third-party clients to consume.

Today we master professional conventions: plural nouns for endpoints, proper status codes, filtering, sorting, pagination, and versioning.

Prerequisites

  • Days 07–10: Express routing, query parameters, GET, POST, PUT, PATCH, and DELETE methods.
  • Day 12: Centralized error handling and status codes.

Detailed Lessons & Code Demonstrations

Lesson 13.1

RESTful Naming Conventions & URL Hierarchy

Good REST APIs treat everything as a resource represented by nouns, never verbs. Actions are defined by HTTP methods (`GET`, `POST`, `PUT`, `DELETE`).

naming-conventions.txt 
# BAD (Using verbs and inconsistent naming)
GET    /getUsers
POST   /createUser
GET    /getUserPosts?id=5

# GOOD (Clean RESTful plural nouns & nested resources)
GET    /api/v1/users           # Retrieve all users
POST   /api/v1/users           # Create a new user
GET    /api/v1/users/42        # Retrieve user with ID 42
PUT    /api/v1/users/42        # Replace user 42
DELETE /api/v1/users/42        # Delete user 42
GET    /api/v1/users/42/posts  # Retrieve posts belonging to user 42
Key Takeaway:

Always use plural nouns for collections (`/users`, `/products`, `/orders`) and include versioning (`/api/v1/`).

Lesson 13.2

Pagination, Filtering, and Sorting in Express

When collections grow large, returning thousands of records overwhelms servers and networks. We use query parameters to paginate (`page`, `limit`), filter (`status=active`), and sort (`sort=-createdAt`).

pagination.js 
// Express Pagination & Filtering Controller Example
app.get('/api/v1/products', (req, res) => {
    let results = [...allProducts];

    // 1. Filtering by category
    if (req.query.category) {
        results = results.filter(p => p.category === req.query.category);
    }

    // 2. Pagination (page & limit)
    const page = parseInt(req.query.page) || 1;
    const limit = parseInt(req.query.limit) || 10;
    const startIndex = (page - 1) * limit;
    const endIndex = page * limit;

    const paginatedResults = results.slice(startIndex, endIndex);

    res.json({
        success: true,
        page,
        limit,
        total: results.length,
        count: paginatedResults.length,
        data: paginatedResults
    });
});

Daily Project: Professional RESTful API with Pagination & Filtering

Build a Versioned REST API with Query Filtering

Project Phase 2 - Day 13

Description: Build a fully compliant REST API featuring versioned routes (`/api/v1/books`), pagination, category filtering, proper status codes, and centralized error handling.

Key Requirements:

  • Use RESTful plural noun endpoints with `/api/v1/` prefix.
  • Implement query parameter pagination (`page`, `limit`) and filtering (`genre`).
  • Return semantic status codes (200, 201, 204, 400, 404).
server.js 
// Professional RESTful API Server (Day 13 Project)
const express = require('express');
const app = express();
const PORT = 3000;

app.use(express.json());

// Mock Database
let books = [
    { id: 1, title: 'Clean Code', author: 'Robert C. Martin', genre: 'Programming', price: 29.99 },
    { id: 2, title: 'The Pragmatic Programmer', author: 'Andrew Hunt', genre: 'Programming', price: 34.99 },
    { id: 3, title: 'Atomic Habits', author: 'James Clear', genre: 'Self-Help', price: 21.99 },
    { id: 4, title: 'Deep Work', author: 'Cal Newport', genre: 'Productivity', price: 24.99 },
    { id: 5, title: 'Designing Data-Intensive Applications', author: 'Martin Kleppmann', genre: 'Architecture', price: 45.99 }
];

// 1. GET ALL BOOKS (With Filtering & Pagination)
app.get('/api/v1/books', (req, res) => {
    let results = [...books];

    // Filter by genre query param
    if (req.query.genre) {
        results = results.filter(b => b.genre.toLowerCase() === req.query.genre.toLowerCase());
    }

    // Pagination
    const page = parseInt(req.query.page) || 1;
    const limit = parseInt(req.query.limit) || 3;
    const startIndex = (page - 1) * limit;
    const endIndex = page * limit;

    const paginatedBooks = results.slice(startIndex, endIndex);

    res.status(200).json({
        success: true,
        page,
        limit,
        totalResults: results.length,
        totalPages: Math.ceil(results.length / limit),
        data: paginatedBooks
    });
});

// 2. GET SINGLE BOOK BY ID
app.get('/api/v1/books/:id', (req, res, next) => {
    const book = books.find(b => b.id === parseInt(req.params.id));
    if (!book) {
        const err = new Error('Book not found with that ID');
        err.statusCode = 404;
        return next(err);
    }
    res.status(200).json({ success: true, data: book });
});

// 3. CREATE NEW BOOK
app.post('/api/v1/books', (req, res, next) => {
    const { title, author, genre, price } = req.body;
    if (!title || !author || !price) {
        const err = new Error('Please provide title, author, and price');
        err.statusCode = 400;
        return next(err);
    }

    const newBook = { id: books.length + 1, title, author, genre: genre || 'General', price };
    books.push(newBook);

    res.status(201).json({ success: true, message: 'Book created successfully', data: newBook });
});

// 4. DELETE BOOK
app.delete('/api/v1/books/:id', (req, res, next) => {
    const index = books.findIndex(b => b.id === parseInt(req.params.id));
    if (index === -1) {
        const err = new Error('Book not found for deletion');
        err.statusCode = 404;
        return next(err);
    }

    books.splice(index, 1);
    res.status(200).json({ success: true, message: 'Book deleted successfully' });
});

// Centralized Error Handler
app.use((err, req, res, next) => {
    res.status(err.statusCode || 500).json({
        success: false,
        error: err.message || 'Internal Server Error'
    });
});

app.listen(PORT, () => {
    console.log(`🚀 REST API server running at http://localhost:${PORT}`);
});

Quick Concepts

1. What status code represents successful resource creation?

Answer: 201 Created

2. What naming convention is standard for REST resource collections?

Answer: Plural nouns (e.g., /users, /products)

3. What query parameters are typically used for pagination?

Answer: page and limit (or offset and limit)

Day 13 Quick Revision Cheat-Sheet

Plural Nouns

Use resource collections with plural nouns (`/users`, `/posts`) instead of verbs.

Semantic Codes

Use 200 (OK), 201 (Created), 400 (Bad Request), 404 (Not Found), 500 (Server Error).

Pagination

Control large datasets using query parameters like `?page=1&limit=10`.

Versioning

Prefix API routes with version identifiers such as `/api/v1/`.
