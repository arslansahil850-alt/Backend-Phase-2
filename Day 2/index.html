Introduction & Prerequisites

What & Why Modular Architecture?

As backend applications grow from a single script into complex systems with thousands of lines of code, writing everything in one file becomes unmaintainable.

Node.js solves this through the Module System. A module is an encapsulated block of code that performs a specific task and exports its functionality so other files can import and reuse it safely.

Prerequisites

  • Day 01 Knowledge: Familiarity with Node.js runtime, globals (`__dirname`), and terminal execution.
  • JavaScript Functions & Objects: Understanding scope, object literals, and callback execution.
  • File Navigation: Knowing relative file paths (`./` vs `../`).

Detailed Lessons & Code Demonstrations

Lesson 2.1

The CommonJS Standard (`require` & `module.exports`)

Node.js defaults to the CommonJS module system. In CommonJS, every single JavaScript file is treated as a distinct, independent module. Variables, functions, and classes defined inside a file are private by default unless explicitly exported.

math.js (Module Definition) 
// math.js - Custom Utility Module
const add = (a, b) => a + b;
const subtract = (a, b) => a - b;
const PI = 3.14159;

// Exporting functions and values via module.exports
module.exports = {
    add,
    subtract,
    PI
};
app.js (Module Consumer) 
// app.js - Importing custom module using require()
const math = require('./math');

console.log("Addition result:", math.add(10, 5));     // 15
console.log("Subtraction result:", math.subtract(10, 5)); // 5
console.log("Value of PI:", math.PI);                 // 3.14159
Line-by-Line Breakdown:
  • require('./math'): Tells Node to locate `math.js` relative to the current file, execute it, and return its `module.exports` object.
  • module.exports: The special object that Node evaluates and returns when another file requires this module.
Lesson 2.2

Module Wrapper Function

Before Node.js executes your code, it wraps every module inside a hidden wrapper function known as the Module Wrapper. This wrapper ensures that variables are scoped locally to the file rather than leaking to the global object.

Hidden Wrapper Structure 
(function(exports, require, module, __filename, __dirname) {
    // Your module code lives entirely inside here!
});

This explains why variables like __dirname and module are magically available in every file without needing to declare them!

Lesson 2.3

Exporting Single Functions or Classes

Instead of exporting an object containing multiple functions, you can also export a single constructor function, class, or utility directly by assigning it to `module.exports`.

logger.js 
// logger.js - Exporting a single function directly
module.exports = function(message) {
    const timestamp = new Date().toISOString();
    console.log(`[LOG - ${timestamp}]: ${message}`);
};
server.js 
// server.js
const logger = require('./logger');

logger("Server database connection initialized successfully.");

Daily Project: Modular Calculator & Statistics CLI

Build a Multi-File Modular Statistics Calculator

Project Phase 2 - Day 02

Description: Build a modular Node.js application divided into separate files (`math.js`, `stats.js`, and `app.js`). The application will calculate array statistics (sum, average, max, min) using imported CommonJS modules.

Key Requirements:

  • Create `math.js` for basic arithmetic functions.
  • Create `stats.js` that requires `math.js` and computes array average and total sum.
  • Create `app.js` as the main entry point to execute and log formatted results.
stats.js 
// stats.js - Array Statistics Module
const math = require('./math');

function calculateStats(numbers) {
    if (!numbers || numbers.length === 0) return null;

    let sum = 0;
    for (let num of numbers) {
        sum = math.add(sum, num);
    }

    const average = sum / numbers.length;
    const max = Math.max(...numbers);
    const min = Math.min(...numbers);

    return {
        count: numbers.length,
        sum,
        average,
        max,
        min
    };
}

module.exports = { calculateStats };

Conceptual Knowledge Checks

True or False

1. In CommonJS, variables declared in one file are automatically global across all files.

FALSE: Each file is encapsulated in its own module scope.

2. The `require()` function is used to import modules in CommonJS.

TRUE: `require()` loads and returns exported module data.

3. Node wraps every module in a hidden function wrapper before execution.

TRUE: The Module Wrapper provides `__dirname`, `module`, and `exports`.

Quick Concepts

1. What object is used to expose functions from a CommonJS module?

Answer: module.exports (or shorthand `exports`).

2. What module system does Node.js use by default?

Answer: CommonJS.

3. What happens if you require a folder without specifying a filename?

Answer: Node looks for an `index.js` file inside that folder by default.

Day 02 Quick Revision Cheat-Sheet

CommonJS

Default Node module standard using require() and module.exports.

Encapsulation

Variables inside a module are private by default and do not pollute global scope.

Importing

Use relative paths (./ or ../) for custom local file modules.

Folder Index

Requiring a directory automatically resolves to index.js inside that folder.
